# React Native 会议房间测试用例

本文档覆盖纯 React Native 会议房间流程，测试范围包括 `react-native-webrtc`、`mediasoup-client`、后端 `/media/room/*` 接口，以及 SFU Socket.io 信令协议。

## 会议创建与加入

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 创建立即会议 | 选择“立即会议”并创建会议。 | 调用 `/media/room/create`，参数 `type=1`；创建成功后进入会前预览。 |
| 创建预约会议 | 选择“预约会议”，填写未来日期和时间后创建。 | 调用 `/media/room/create`，参数 `type=2`；创建成功后返回会议列表。 |
| 拒绝非法预约时间 | 使用早于当前时间的开始时间创建预约会议。 | 阻止提交，并提示“预约会议开始时间必须晚于当前时间”。 |
| 验证会议号 | 输入有效会议号并点击验证。 | 调用 `/media/room/validate-no`；展示会议卡片。 |
| 加入预验证成功 | 点击加入一个允许进入的会议。 | 调用 `/media/room/join`；当 `allowed=true` 时进入会前预览。 |
| 加入预验证失败 | 后端返回 `allowed=false`。 | 不进入房间，并展示后端返回的提示信息。 |

## 本地媒体发布

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 开启麦克风和摄像头入会 | 授权相机和麦克风后进入房间。 | 创建 send/recv transport，发布本地音频和视频 producer，并显示本地摄像头画面。 |
| 关闭摄像头入会 | 在会前预览关闭摄像头后进入房间。 | 不发布视频；本地画面显示头像或“摄像头已关闭”。 |
| 关闭麦克风入会 | 在会前预览关闭麦克风后进入房间。 | 不发布音频或音频处于禁用状态；本地成员状态显示静音。 |
| 拒绝相机权限 | Android 端拒绝 `CAMERA` 权限。 | 不进入会议，并显示相机权限提示。 |
| 拒绝麦克风权限 | Android 端拒绝 `RECORD_AUDIO` 权限。 | 不进入会议，并显示麦克风权限提示。 |

## 远端订阅与多人媒体

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 第二名参会者加入 | A 已在房间中，B 加入。 | A 收到 `newPeer/newProducer`；B 消费 A 的 producer；双方可看到视频并听到音频。 |
| 第三名参会者加入 | A、B 已在房间中，C 加入。 | C 消费 A/B 已有 producer；A/B 收到并消费 C 的 producer。 |
| producer 早于 recv transport 到达 | 加入中的客户端尚未创建 recv transport 时，房间内产生新的 producer。 | producer 进入待处理队列；device 和 recv transport ready 后自动订阅。 |
| 远端仅音频流 | 远端成员关闭视频但保留音频。 | 本地仍可听到音频，但不显示远端视频画面。 |
| 远端成员离开 | B 离开会议。 | A/C 的成员列表移除 B，并清理 B 对应的 consumer、track、producer 映射和 remote stream。 |
| 远端 producer 关闭 | B 关闭视频 producer。 | A/C 将 B 的画面切换为“摄像头已关闭”，不保留失效视频 track。 |

## 参会者自控

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 自己静音 | 点击“静音”。 | 本地 audio track 被禁用，SFU `toggleAudio` 成功，远端显示该成员静音。 |
| 自己开麦 | 点击“开麦”。 | 本地 audio track 启用或重新发布，远端显示音频恢复。 |
| 自己关闭视频 | 点击“关视频”。 | 本地 video track 被禁用，SFU 广播 `producerStateChanged`，远端显示摄像头关闭。 |
| 自己开启视频 | 点击“开视频”。 | 本地预览恢复，远端视频显示恢复。 |
| 切换摄像头 | 点击“切换摄像头”。 | 前后摄像头切换，producer 不应永久中断。 |

## 主持人控制

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 主持人静音单个成员 | 主持人静音成员 B。 | SFU `hostToggleAudio` 成功；B 收到控制并禁用本地 audio track；所有客户端显示 B 静音。 |
| 主持人关闭单个成员视频 | 主持人关闭成员 B 的视频。 | B 收到控制并禁用本地 video track；所有客户端显示 B 摄像头关闭。 |
| 主持人全体静音 | 主持人点击“全体静音”。 | 非主持人成员全部静音，客户端 UI 状态同步。 |
| 主持人全体关视频 | 主持人点击“全体关视频”。 | 非主持人成员视频全部关闭，客户端 UI 状态同步。 |
| 主持人移出成员 | 主持人移出 B。 | B 收到 `removedFromRoom` 并退出会议；其他客户端从成员列表移除 B。 |
| 非主持人尝试主持人控制 | 普通成员绕过 UI 发送主持人控制事件。 | 服务端应拒绝该请求；需要重点验证 SFU 侧主持人鉴权。 |

## Spotlight 焦点模式

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 本地选择焦点 | 点击某个成员的小窗。 | 主舞台切换为该成员。 |
| 主持人设置焦点 | 主持人将 B 设为焦点。 | 所有客户端收到 `spotlightChanged`，主舞台显示 B。 |
| 主持人取消焦点 | 主持人点击“取消焦点”。 | 所有客户端退出全局焦点模式，回到本地选择或活跃成员布局。 |
| 普通成员申请焦点 | B 点击“申请焦点”。 | 主持人收到 `spotlightRequest`。 |
| 焦点订阅层级优化 | 将 B 设为焦点。 | B 的 video consumer 请求高层级，非焦点视频 consumer 请求较低层级。 |

## 移动端网络与生命周期

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| Socket 断开 | 会议中关闭网络。 | UI 进入重连或恢复状态，应用不崩溃。 |
| 网络恢复 | 重新打开网络。 | Socket 重连，`recover()` 执行，客户端重新加入房间、重建 transport、重新发布本地媒体并重新订阅远端媒体。 |
| App 从后台回到前台 | 按 Home 键后重新打开应用。 | 如果媒体状态不是 ready，应用调用 `recover()`。 |
| Wi-Fi 和蜂窝网络切换 | 会议中切换网络类型。 | 媒体链路可恢复，远端客户端重新看到本地媒体。 |
| 锁屏恢复 | 锁屏一段时间后解锁。 | 会议可恢复，不残留失效 consumer 或 stream。 |

## 关闭与清理

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 普通成员正常离会 | 点击挂断。 | 本地 tracks stop，producers/consumers/transports close，并执行 socket leave/disconnect。 |
| 主持人关闭会议 | 主持人关闭会议。 | 所有客户端收到 `roomClosed` 并退出房间。 |
| 反复加入和离开 | 连续加入并离开同一房间 5 次。 | 不出现重复远端画面、失效 stream 或明显内存增长。 |
| 多人长时间会议 | 至少 3 名参会者持续会议 30 分钟。 | 远端状态稳定，成员进退清理正常，音频路由保持正确。 |

## 优先回归测试集

时间有限时优先执行以下用例：

1. 三人入会与远端订阅。
2. producer 早于 recv transport 到达。
3. 主持人强制关闭音频和视频。
4. 网络断开与恢复。
5. `peerLeft` 和 `producerClosed` 清理。
6. spotlight 布局与 simulcast 层级优化。
